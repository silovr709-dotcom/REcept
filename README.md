# РЕцепт — сайт семейного мебельного ателье (Тверь)

Конверсионный сайт мебельного ателье «РЕцепт». Главная задача сайта — не
«показать красивые кухни», а довести посетителя до обращения к Роберту и Кате.

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS v4 ·
self-hosted шрифты · без анимационных библиотек.

---

## 🚀 Быстрый старт

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # production-сборка
npm start       # запуск production-сборки
npm run typecheck
```

## ⚠️ Что ещё нужно проверить и дополнить

### 1. Собственное производство — сверьте формулировку

Во ВКонтакте вы сами разбираете вопрос «почему у нас нет собственного
производства». Поэтому я убрал с сайта все утверждения вида «мы производим» и
переформулировал честно: заказ размещается на производстве, а проектирование,
контроль, доставка и сборка — на вас. Текст в `src/data/content.ts`
(шаг 07 процесса и вопрос «У вас есть собственное производство?») —
**перечитайте и поправьте под свою формулировку.**

### 2. Роли Роберта и Кати

Сейчас у обоих стоит «Руководитель» — так указано в карточках во ВКонтакте.
Если хотите разделить зоны ответственности (например, проектирование и
монтаж), впишите в `src/data/content.ts` → `team`.

### 3. Фотографии Роберта и Кати — `public/images/team/`

Положите файлы и укажите путь в поле `photo`. Блок корректно работает и без
них, но живые лица усиливают весь раздел «О нас».

### 4. Куда приходят заявки — `.env.local`

Скопируйте `.env.example` в `.env.local`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=tver-kuhni11@yandex.ru
SMTP_PASSWORD=пароль_приложения_Яндекс_Почты
LEAD_EMAIL_TO=tver-kuhni11@yandex.ru
LEAD_EMAIL_FROM="Сайт РЕцепт" <tver-kuhni11@yandex.ru>
NEXT_PUBLIC_SITE_URL=https://tver-kuhni.ru
```

Для Яндекс Почты нужен **пароль приложения**, а не обычный пароль от аккаунта.

Пока почта не настроена, заявки **не теряются**: они пишутся в
`.leads/leads.jsonl` и в логи сервера, а человек видит нормальное
подтверждение.

### 5. Часы работы

Полного расписания мы не знаем (на Яндекс Картах видно только открытие в
10:00), поэтому текстом его не пишем — актуальное показывает виджет карты.
Если хотите зафиксировать, впишите `WORKING_HOURS` в `src/data/site.ts`.

### 6. Telegram и WhatsApp

Если заведёте — раскомментируйте `TELEGRAM_USERNAME` / `WHATSAPP_RAW`
в `src/data/site.ts`, кнопки появятся сами.

## 🧩 Как добавлять контент

Всё через админку: **/admin**. Правка кода больше не требуется ни для
проектов, ни для отзывов, ни для текстов.

Что осталось важным при наполнении:

- **Описания проектов** — только то, что действительно видно на фотографии.
  Поля «площадь», «срок», «бюджет» и «история заказчика» заполняйте лишь
  реальными данными: пустые поля на сайте просто не показываются.
- **Отзывы** — дословно, сокращения многоточием. Рядом на сайте стоит живой
  виджет Яндекса, и любой посетитель может сверить.
- **Детали и фактуры** — крупные планы: профиль, кромка, стык, подсветка.
  Именно по ним видно, что мебель делалась под конкретное помещение.

## 🔐 Админка: /admin

Весь контент сайта меняется через панель управления — трогать код не нужно.

### Как включить

Добавьте в `.env.local` две строки и перезапустите сайт:

```
ADMIN_PASSWORD=придумайте_пароль
AUTH_SECRET=длинная_случайная_строка
```

Секрет удобно сгенерировать командой `openssl rand -hex 32`. Он нужен, чтобы
подписывать вход: без него подделать сессию невозможно. Пока переменных нет,
админка сама расскажет, что добавить, и внутрь никого не пустит.

Вход живёт по адресу **/admin**. Страница закрыта от поисковиков и в
`robots.txt`, и заголовком `X-Robots-Tag`.

### Что можно менять

| Раздел | Что внутри |
|---|---|
| **Заявки** | Все заявки с сайта. Дубль на случай, если письмо не дошло |
| **Проекты портфолио** | Фото, описание, материалы, решения, компоновка. Порядок — стрелками. Можно скрыть проект, не удаляя |
| **Детали и фактуры** | Крупные планы фурнитуры и материалов |
| **Отзывы и рейтинг** | Цитаты с Яндекс Карт и цифры рейтинга |
| **Видео** | Ссылки на ролики из сообщества ВКонтакте и обложки к ним |
| **Первый экран** | Заголовок, подзаголовок, кнопки, цифры, главное фото, блок «Зачем мы нужны», блок о Роберте и Кате |
| **Блоки страниц** | Направления, преимущества, шаги процесса, сроки, цена, карточки руководителей |
| **Вопросы и возражения** | Блок «А если…» и частые вопросы (попадают в микроразметку) |
| **Контакты и реквизиты** | Телефоны, почта, адрес, соцсети, карточка Яндекса, счётчик Метрики, условия работы, заголовок и описание для поиска |
| **Резервная копия** | Скачать/восстановить весь контент, откатить раздел к исходному виду |

Изменения появляются на сайте **сразу после сохранения** — пересобирать
проект не нужно.

### Как это устроено

- Контент лежит в JSON-файлах в папке `content/`, фотографии — в
  `public/uploads/`. Никакой базы данных: файлы можно открыть, прочитать
  глазами и положить в архив.
- Ролики ВКонтакте не грузятся вместе со страницей: до нажатия показывается
  обложка, плеер подключается только по клику.
- Загруженные фотографии автоматически поворачиваются по EXIF, уменьшаются
  до 2400 px, переводятся в WebP и получают размытую заглушку. Снимок с
  телефона на 300 кБ превращается примерно в 140 кБ, а вёрстка не «прыгает».
- Вход — подписанная кука на 12 часов. После восьми неверных попыток
  подряд вход блокируется на 10 минут.
- Проверка доступа стоит в middleware, то есть **до** выполнения кода
  страниц: без входа наружу не уходит ни строчки данных.

### ⚠️ Важно про данные и обновления

Папки `content/` и `public/uploads/` — это **живые данные**, они намеренно не
хранятся в git. Иначе каждое обновление кода конфликтовало бы с правками,
сделанными через админку.

Из этого следуют два правила:

1. **Перед обновлением сайта скачайте резервную копию** в разделе
   «Резервная копия». Это один файл со всем текстом и настройками.
2. **При переезде на новый сервер** перенесите руками папку
   `public/uploads/` — фотографии в резервную копию не входят.

На чистом сервере сайт поднимется с исходным наполнением: оно зашито в
`src/lib/content/seed.ts` и переносится в `content/` при первом запуске.

## 🎯 Конверсионная логика

Путь посетителя: **внимание → интерес → понимание → доверие → снятие страха →
желание обсудить → контакт.**

| Блок | Какую задачу решает |
|---|---|
| Hero | За 5 секунд: что, где, кто, чем отличается, что нажать |
| «Мы забираем головную боль» | Главная боль клиента: он один между мебельщиком и прорабом |
| Что мы делаем | Расширяет запрос: не только кухни |
| Портфолио | Визуальное доказательство → сразу возврат к действию |
| Процесс из 10 шагов | Снимает страх неизвестности + показывает, как мало нужно от клиента |
| Когда приходить | Честная причина не откладывать (вместо фейковой срочности) |
| Преимущества | Каждое условие связано с выгодой, а не с иконкой |
| Цена | Объясняет, почему нет прайса, и предлагает бесплатный расчёт |
| Роберт и Катя | Персональная ответственность вместо «нашей команды» |
| Возражения | Отвечает на «а если…» до того, как человек уйдёт |
| FAQ | Добивает остаточные вопросы |
| Финальный CTA | Не «спасибо за внимание», а приглашение к разговору |

**Единая механика CTA.** Все кнопки — компонент `CtaButton`. Он открывает
короткую форму поверх страницы, поэтому человек не теряет контекст и не
скроллит в конец. Заголовок формы меняется под контекст кнопки. Если JS не
загрузился, кнопка ведёт к форме `#zayavka` внизу страницы.

**Форма.** Три поля (имя, контакт, комментарий) + необязательные вложения.
Рядом всегда объяснено, что будет дальше, и что это ни к чему не обязывает.
После отправки человек видит не «Спасибо!», а описание следующего шага.

**Чего на сайте нет и не будет:** выдуманных отзывов и цифр, зачёркнутых цен,
таймеров, «только сегодня», «№1 в Твери», стоковых фотографий.

## ⚡️ Производительность и доступность

- Все изображения — через `next/image`: AVIF/WebP, responsive `srcset`,
  lazy-loading, blur-placeholder, `priority` только для LCP-кадра.
- Шрифты self-hosted (`woff2`, кириллица отдельным subset), `preload`
  + `font-display: swap`. Внешних CDN нет.
- Анимации — только CSS + `IntersectionObserver`, без анимационных библиотек.
  First Load JS ≈ 119 кБ.
- `prefers-reduced-motion` отключает всю анимацию, включая заставку.
- Семантическая разметка, один `h1` на страницу, `alt` у всех изображений,
  видимый фокус, ловушка фокуса в модальном окне, skip-link, контраст текста
  проверен по WCAG AA.
- Заставка загрузки не задерживает: уходит сразу после `load`, при повторном
  визите — ускоренная версия, при отключённом JS не показывается вовсе,
  плюс два независимых страховочных таймера.
  Длительность меняется одной строкой в `src/components/LoaderController.tsx`
  (`minDuration`: 1700 мс на первый визит, 500 мс на повторный).

## 📊 Аналитика

Впишите номер счётчика Яндекс.Метрики в админке: **Контакты и реквизиты →
Аналитика**. Пока номер не указан, ни один сторонний скрипт на сайт не
загружается.

Как только счётчик подключён, сами собой начинают работать четыре цели:

| Цель | Когда срабатывает |
|---|---|
| `lead_sent` | Заявка успешно отправлена — **главная цель** |
| `lead_form_open` | Нажали любую кнопку с призывом и открыли форму |
| `phone_click` | Нажали на номер телефона |
| `messenger_click` | Перешли в мессенджер, соцсеть или запустили видео |

В Метрике эти цели нужно один раз завести как «JavaScript-событие» с такими
же именами. К каждой цели передаётся параметр `source` — по нему видно,
какая именно кнопка сработала: `hero`, `price`, `mobile-bar`, `process`
и так далее.

Заявка отправляется без перехода на страницу «спасибо» — это удобнее для
человека, но означает, что считать конверсию можно только по цели
`lead_sent`. Без неё статистика будет пустой.

## ↪️ Переезд со старого сайта

Если новый сайт встаёт на домен, где уже работал старый, каждый его адрес
нужно перенаправить на новый — иначе накопленные позиции и внешние ссылки
упрутся в 404.

Список редиректов задаётся в `next.config.ts` в разделе `redirects()`:

```ts
{ source: '/kuhni', destination: '/kuhni-na-zakaz', permanent: true }
```

`permanent: true` — это код 301, «переехали навсегда»: поисковики переносят
вес страницы на новый адрес. Пришлите список страниц старого сайта — по нему
составляется таблица соответствий.

## 📦 Деплой

Подойдёт любая площадка с поддержкой Node.js (Vercel, Timeweb Cloud, Selectel,
свой VPS):

```bash
npm ci
npm run build
npm start          # или pm2 / systemd
```

Не забудьте переменные окружения из `.env.example` и реальный
`NEXT_PUBLIC_SITE_URL` — от него зависят canonical-ссылки, sitemap и OG.

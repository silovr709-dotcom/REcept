# Запуск единой системы: что нажать, шаг за шагом

Инструкция для человека, а не для программиста. Делать строго по порядку.
Всего пять шагов, примерно час с перерывами на ожидание.

| Шаг | Что даёт | Сколько времени |
| --- | --- | --- |
| 1 | Сайт `рецепт-тверь.рф` оживает | 5 минут + 5 минут ожидания |
| 2 | Рабочая версия калькулятора становится главной | 5 минут |
| 3 | Из репозитория убираются чужие паспортные данные | 3 минуты |
| 4 | Калькулятор получает кнопку «Отправить в кабинет» | 20 минут, из них ваших — 5 |
| 5 | Ключ кабинета прописывается на хостинге | 15 минут |
| ✔ | Проверка: отправляем документ себе | 10 минут |

## Шаг 1. Включить сайт на домене `рецепт-тверь.рф`

Сейчас сайт собирается автоматически, но не выкладывается на хостинг: не хватает
одного пароля. Всё остальное уже прописано.

1. Открыть в браузере:
   **https://github.com/silovr709-dotcom/REcept/settings/secrets/actions**
   (если попросит войти — войти своей учётной записью GitHub).
2. Нажать зелёную кнопку **New repository secret**.
3. В поле **Name** написать ровно так, большими буквами:

   ```
   FTP_PASSWORD
   ```

4. В поле **Secret** вставить **пароль FTP того хостинга reg.ru**, где лежит
   калькулятор (тот же аккаунт `u3683615`). Это тот самый пароль, которым вы
   заходите в FileZilla или в «Менеджер файлов».
5. Нажать **Add secret**.
6. Перейти на вкладку **Actions**:
   **https://github.com/silovr709-dotcom/REcept/actions**
   Сверху выбрать слева **«Выгрузка сайта на хостинг»** → справа кнопка
   **Run workflow** → ещё раз **Run workflow**.
7. Подождать 4–6 минут. Когда напротив запуска появится зелёная галочка —
   открыть **https://рецепт-тверь.рф** и убедиться, что сайт открылся.

> Если галочка красная — откройте запуск, прокрутите до красной строки и
> пришлите мне её текст. Чаще всего это просто опечатка в пароле.

Кабинет после этого живёт по адресу **https://рецепт-тверь.рф/kabinet/** —
он понадобится на шаге 5.

## Шаг 2. Сделать рабочую версию калькулятора главной

В репозитории калькулятора главная ветка `main` отстала на три недели: в ней нет
ни CRM, ни сервера, ни документов. Нужно влить рабочую ветку в главную.
Конфликтов нет, я проверил — ничего не потеряется.

1. Открыть:
   **https://github.com/silovr709-dotcom/Calculator/compare/main...arena/78834e40-calculator**
2. Под заголовком должна быть зелёная надпись **Able to merge**.
   Нажать зелёную кнопку **Create pull request**.
3. Заголовок оставить как есть, нажать ещё раз **Create pull request**.
4. На открывшейся странице нажать **Merge pull request** → **Confirm merge**.
5. Кнопку **Delete branch** после слияния **не нажимать** — рабочая ветка ещё нужна.

После слияния GitHub сам соберёт калькулятор и выложит его на хостинг: это
настроено давно и работает. Проверить можно на вкладке
**https://github.com/silovr709-dotcom/Calculator/actions** — должны появиться два
новых запуска с зелёными галочками.

## Шаг 3. Убрать из репозитория чужие персональные данные

В открытой части репозитория калькулятора лежат два настоящих клиентских
документа с паспортными и контактными данными:

* `ДОГОВОР ЕКАТЕРИНА НАЗАРОВА ПЛАНКИ.docx`
* `Бланк Заказа Александр Климов .doc`

Репозиторий открыт всему интернету. Шаблон договора из них уже вынут в
`docs/шаблон-договора.md`, сами файлы больше не нужны.

1. Открыть **https://github.com/silovr709-dotcom/Calculator**
2. Щёлкнуть по файлу `ДОГОВОР ЕКАТЕРИНА НАЗАРОВА ПЛАНКИ.docx` в списке.
3. Справа сверху значок **корзины** (Delete file). Если его не видно — нажать
   кнопку с тремя точками **⋯** и выбрать **Delete file**.
4. Внизу страницы нажать зелёную **Commit changes** → **Commit changes**.
5. Повторить то же самое для `Бланк Заказа Александр Климов .doc`.

> Это убирает файлы из текущей версии. Они останутся в истории репозитория —
> полностью вычистить историю можно отдельно, скажите, если нужно.

## Шаг 4. Добавить калькулятору кнопку «Отправить в кабинет»

Весь код уже написан и проверен, он лежит в этом репозитории в папке
`integration/calculator/`. Его нужно перенести в репозиторий калькулятора.
Самому копировать файлы руками не нужно — проще поручить это новой сессии Arena,
которая работает с репозиторием калькулятора.

1. Открыть Arena и создать **новую сессию с репозиторием
   `silovr709-dotcom/Calculator`** (так же, как создавалась эта — с REcept).

silovr709-dotcom/REcept, в папке integration/calculator/.
Читать оттуда файлы можно так:
  gh api repos/silovr709-dotcom/REcept/contents/integration/calculator/README.md \
     --jq '.content' | base64 -d

Сделай ровно то, что написано в integration/calculator/README.md:

1. Скопируй без изменений:
   server/cabinet.php               → server/api/cabinet.php
   app/src/lib/cabinetPayload.ts    → app/src/lib/cabinetPayload.ts
   app/src/lib/cabinetPayload.test.ts → app/src/lib/cabinetPayload.test.ts

Ничего не придумывай сверх README: себестоимость, наценка, цена за строку,

## Шаг 5. Прописать ключ кабинета на хостинге калькулятора

Это единственное место, где нужен секретный ключ. Он даёт полный доступ к базе
кабинета, поэтому живёт только в одном файле на сервере и нигде больше: ни в
GitHub, ни в браузере.

### 5.1. Взять ключ в Supabase

1. Открыть **https://supabase.com/dashboard** и войти.
2. Выбрать проект **recept-kabinet** (идентификатор `iswkzclegjcbhxaatmbb`).
3. Слева внизу **Project Settings** (шестерёнка) → раздел **API Keys**.
4. В списке найти строку с именем **`calculator_bridge`** — я создал её заранее.
5. Нажать **Reveal** (или значок глаза) и **Copy**. Получится длинная строка,
   начинающаяся с `sb_secret_`.

### 5.2. Вписать ключ на хостинг

1. Войти в панель хостинга reg.ru (ISPmanager) → **«Менеджер файлов»**.
2. Перейти в папку сайта калькулятора:
   `/www/u3683615.isp.regruhosting.ru/api/`
3. Найти файл **`config.php`**.

   **Если файл есть** — открыть его на редактирование (значок карандаша) и
   добавить три строки перед закрывающей скобкой `];`, не трогая то, что уже
   написано:

   ```php
       'cabinetUrl'    => 'https://iswkzclegjcbhxaatmbb.supabase.co',
       'cabinetSecret' => 'сюда вставить скопированный ключ sb_secret_…',
       'cabinetSite'   => 'https://xn----dtbhac1degob3b6e.xn--p1ai',
   ```

   **Если файла нет** — создать новый файл с именем `config.php` и таким
   содержимым целиком:

   ```php
   <?php
   return [
       'cabinetUrl'    => 'https://iswkzclegjcbhxaatmbb.supabase.co',
       'cabinetSecret' => 'сюда вставить скопированный ключ sb_secret_…',
       'cabinetSite'   => 'https://xn----dtbhac1degob3b6e.xn--p1ai',
   ];
   ```

4. Сохранить.

> `xn----dtbhac1degob3b6e.xn--p1ai` — это и есть `рецепт-тверь.рф`, записанный
> латиницей. Так надёжнее: не все программы понимают кириллицу в адресе.
> **Если шаг 1 ещё не сделан**, временно поставьте вместо него
> `https://silovr709-dotcom.github.io/REcept` — кабинет пока живёт там.

### 5.3. Проверить

Открыть в браузере, предварительно войдя в калькулятор:

**https://рецепт-про.рф/api/index.php?r=cabinet/health**

Должно появиться что-то вроде:

```json
{"ok":true,"configured":true,"url":"https://iswkzclegjcbhxaatmbb.supabase.co","site":"https://xn----dtbhac1degob3b6e.xn--p1ai","curl":true}
```

* `configured: true` — ключ на месте;
* `curl: true` — хостинг умеет ходить наружу.

Если видно `configured: false` — файл `config.php` не там или в нём опечатка.
Если видно `"Неизвестный запрос к API"` — значит шаг 4 ещё не доехал до хостинга.

## Проверка целиком: отправьте документ сами себе

1. В калькуляторе завести тестовый проект, в клиенте указать **свою почту**.
2. Сделать коммерческое предложение и нажать **«Отправить в кабинет»**.
3. Нажать **«Пригласить в кабинет»** — калькулятор даст ссылку. Открыть её в
   другом браузере (или в режиме инкогнито).
4. Завести пароль, войти. Должны быть видны: проект, состав заказа без цен по
   строкам, итоговая сумма и файл КП.
5. Нажать **«Согласовать»**, написать пару слов.
6. Вернуться в калькулятор: решение клиента видно в карточке проекта.

Если всё так — система работает: один проект, один клиент, документы ходят
в обе стороны.

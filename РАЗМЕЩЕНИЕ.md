# Как поставить сайт на домен рецепт-тверь.рф

Короткая памятка для владельцев. Технических знаний не требует.

Где что лежит:

| Что | Где |
| --- | --- |
| Домен | reg.ru, `рецепт-тверь.рф` |
| Хостинг | reg.ru, тариф «Хост-0» |
| Исходники сайта | GitHub, репозиторий `silovr709-dotcom/REcept` |
| Витрина для проверки | <https://silovr709-dotcom.github.io/REcept/> |

## Важное про кириллический домен

Интернет внутри себя не умеет работать с русскими буквами в адресе.
Поэтому у домена есть второе, «машинное» написание:

| Как видит человек | Как записывает техника |
| --- | --- |
| `рецепт-тверь.рф` | `xn----dtbhac1degob3b6e.xn--p1ai` |

Это один и тот же домен. В адресной строке браузера посетитель всё
равно увидит `рецепт-тверь.рф`. Но **во все технические поля** (панель
хостинга, сертификат, настройки входа в кабинет) вписывается именно
вторая строка. Она уже прописана в сайте: карта сайта,
canonical-ссылки и микроразметка собраны с ней.

## Что нужно сделать — весь список

Четыре шага, 15–20 минут. Три из них в панели reg.ru, один — в GitHub.

1. Создать в панели хостинга WWW-домен `рецепт-тверь.рф` и проверить
   версию PHP.
2. Добавить в GitHub один секрет — пароль FTP. После этого сайт
   выкладывается сам при каждой правке.
3. Выпустить бесплатный сертификат https.
4. Проверить: сайт, форма заявки, кабинет.

Всё остальное — сборка, проверка качества, выгрузка файлов, контроль
того, что на сайте оказалась именно свежая версия — происходит
автоматически на стороне GitHub.

---

### Шаг 1. Домен и папка на хостинге

1. Личный кабинет reg.ru → карточка домена `рецепт-тверь.рф` → убедиться,
   что домен привязан к вашему хостингу (кнопка «Привязать к хостингу»
   или серверы имён `ns1.reg.ru` и `ns2.reg.ru`). Если домен и хостинг
   куплены в одном аккаунте, reg.ru пропишет записи сам.
2. Панель хостинга (ISPmanager) → **«WWW-домены»** → **«Создать
   WWW-домен»** → имя `рецепт-тверь.рф`. Панель сама переведёт его в
   машинное написание и создаст папку
   `www/xn----dtbhac1degob3b6e.xn--p1ai` — так и должно быть.
3. В настройках этого домена проверьте **версию PHP: нужна 7.4 или
   новее** (подойдёт любая из восьмых). PHP нужен ровно для одного
   файла — приёма заявок с форм.
4. Если хостинг положил в папку свою заглушку (`index.html` или
   `index.php` с рекламой тарифа) — удалите её.

На тарифе «Хост-0» этого достаточно: сайт статический, базы данных и
Node.js ему не нужны. Весь сайт весит около 45 МБ.

### Шаг 2. Включить автоматическую выгрузку

Это главный шаг: после него любая правка, сделанная в чате, сама
оказывается на сайте через пару минут. Заливать файлы руками больше
не нужно никогда.

GitHub уже знает, куда выкладывать: сервер
`u3683615.isp.regruhosting.ru`, логин `u3683615`, папка
`/www/xn----dtbhac1degob3b6e.xn--p1ai/`. Не хватает **только пароля**.

1. Откройте GitHub → репозиторий **REcept** → **Settings** →
   **Secrets and variables** → **Actions** → кнопка
   **New repository secret**.
2. **Name:** `FTP_PASSWORD`
   **Secret:** пароль FTP-пользователя хостинга.
   Где взять: ISPmanager → «FTP-пользователи» → выбрать пользователя →
   «Изменить» → при необходимости задать новый пароль.
3. Нажмите **Add secret**.

Пароль видите только вы: GitHub прячет его и не показывает ни в
отчётах о сборке, ни мне. Присылать его в чат не нужно.

**Если логин или сервер окажутся другими**, добавьте рядом ещё секреты —
они перекроют значения по умолчанию:

| Имя секрета | Что вписать | По умолчанию |
| --- | --- | --- |
| `FTP_HOST` | адрес FTP-сервера | `u3683615.isp.regruhosting.ru` |
| `FTP_USER` | логин FTP | `u3683615` |
| `FTP_DIR` | папка сайта | `/www/xn----dtbhac1degob3b6e.xn--p1ai/` |
| `FTP_PROTOCOL` | `ftp`, если хостинг не умеет шифрованный FTPS | `ftps` |

После добавления пароля откройте вкладку **Actions** → «Выгрузка сайта
на хостинг» → кнопка **Run workflow** → в списке `Branch` выбрать
**`arena/01a0e490-recept`** (это рабочая ветка, в ней свежий сайт) →
зелёная **Run workflow**. Это запустит первую выгрузку вручную; дальше
она происходит сама при каждой правке.

На хостинг выкладывается только эта ветка. Если кто-то случайно
отправит изменения в старую ветку `main`, сайт от этого не откатится:
такая сборка проверится, но на хостинг не уедет.

Что выгрузка **никогда не трогает** на хостинге:

* папку `_zayavki` с пришедшими заявками;
* файл `api/lead-config.php` с вашим паролем от почты;
* папку `.well-known`, через которую проверяется сертификат.

### Шаг 3. Включить https

ISPmanager → **«SSL-сертификаты»** → выпустить бесплатный
**Let's Encrypt** для `рецепт-тверь.рф` (и для `www`, если предложит).

Файл `.htaccess` уже настроен так, что после выпуска сертификата сайт
сам переводит посетителей на защищённый адрес и на вариант без `www`.
Проверочная папка `/.well-known/`, по которой Let's Encrypt убеждается,
что домен ваш, из этого перевода исключена — поэтому сертификат можно
выпускать в любой момент, в том числе уже после загрузки сайта.

Пока сертификата нет, браузер на переводе к https покажет
предупреждение — это нормально и проходит сразу после выпуска.

### Шаг 4. Проверить

1. `рецепт-тверь.рф` — должна открыться главная.
2. `рецепт-тверь.рф/portfolio/` — внутренняя страница.
3. `рецепт-тверь.рф/version.txt` — служебный файл, в нём написано,
   какая именно сборка сейчас лежит на сайте и когда она собрана.
   По нему всегда видно, доехала правка или нет.
4. Отправьте тестовую заявку через форму и проверьте почту
   `tver-kuhni11@yandex.ru` (загляните и в «Спам»).
5. `рецепт-тверь.рф/kabinet/` — вход в личный кабинет, он уже настроен
   на этот домен.

## Как теперь выглядит обновление сайта

1. Мы что-то правим в чате — текст, фотографию, раздел.
2. GitHub сам собирает сайт, прогоняет проверку качества
   (`npm run audit`: битые ссылки, вес страниц, якоря, доступность)
   и **выкладывает только изменившиеся файлы** — это занимает секунды.
3. После выгрузки GitHub открывает `рецепт-тверь.рф/version.txt` и
   убеждается, что на сайте оказалась именно новая сборка. Если нет —
   отмечает запуск красным, и это видно во вкладке **Actions**.

Если сборка не прошла проверку, на хостинг не уедет ничего: на сайте
останется предыдущая рабочая версия.

## Запасной путь: загрузить архив руками

Нужен, только если автовыгрузка почему-то недоступна.

**Свежий архив всегда лежит по одной и той же ссылке:**
<https://github.com/silovr709-dotcom/REcept/releases/latest/download/recept-sayt.zip>

Он пересобирается автоматически при каждом изменении сайта.

1. ISPmanager → **«Менеджер файлов»** → папка
   `www` → `xn----dtbhac1degob3b6e.xn--p1ai`.
2. **«Закачать»** → выбрать архив (или «Закачать по ссылке», если
   панель это умеет, — тогда скачивать на компьютер не нужно).
3. Выделить архив → **«Извлечь»** → распаковать **в текущую папку**.
4. Проверить, что `index.html` лежит прямо в папке домена, а не во
   вложенной папке.
5. Архив удалить.

## Заявки с форм: как это работает

Вместе с сайтом загружается файл `api/lead.php` — он принимает заявки.
Порядок такой:

1. заявка **сначала записывается в файл** `_zayavki/zayavki.jsonl`
   (папка закрыта от посторонних) — чтобы ничего не потерялось даже при
   сбое почты;
2. затем уходит письмо на `tver-kuhni11@yandex.ru`;
3. в письме — имя, контакт, сообщение, ответы на вопросы брифа,
   страница, с которой пришла заявка, и приложенные фотографии.

Защита: скрытая ловушка для роботов, ограничение «не больше 5 заявок с
одного адреса за 10 минут», проверка типа и размера вложений
(до 3 файлов, до 8 МБ, только фотографии и PDF).

**Если письма не приходят.** Значит, хостинг не отправляет почту сам.
В папке `api` лежит образец `lead-config.example.php`. Скопируйте его
там же под именем `lead-config.php`, снимите решётки и впишите свои
данные:

```php
define('SMTP_HOST', 'ssl://smtp.yandex.ru');
define('SMTP_PORT', 465);
define('SMTP_USER', 'tver-kuhni11@yandex.ru');
define('SMTP_PASS', 'пароль-приложения-из-Яндекс-ID');
```

Пароль приложения создаётся в Яндекс ID → «Безопасность» → «Пароли
приложений» → «Почта». Обычный пароль от ящика не подойдёт.

Отдельный файл нужен как раз затем, чтобы обновления сайта его не
затирали: пароль вписывается один раз и остаётся навсегда.

## Если захочется вообще без хостинга: домен → GitHub

Сайт уже собран и лежит на серверах GitHub. Нужно только направить на
них домен. Хостинг при этом не нужен совсем — он останется свободным
(например, под почту).

**Почему так лучше:** бесплатно, сертификат https выпускается сам,
а каждое будущее изменение появляется на сайте автоматически — без
перезаливки файлов.

### Шаг 1. Прописать записи у регистратора домена

Зайдите в панель, где куплен домен, раздел «DNS» / «Управление зоной»,
и создайте такие записи:

| Тип | Имя (хост) | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| AAAA | @ | 2606:50c0:8000::153 |
| AAAA | @ | 2606:50c0:8001::153 |
| AAAA | @ | 2606:50c0:8002::153 |
| AAAA | @ | 2606:50c0:8003::153 |
| CNAME | www | silovr709-dotcom.github.io. |

`@` означает «сам домен». Четыре записи A — это не ошибка, они все
нужны. Записи AAAA можно пропустить, если панель их не поддерживает.

Старые записи A, которые указывают на хостинг, нужно удалить —
иначе домен будет открывать то одно, то другое.

### Шаг 2. Сказать мне «записи прописал»

Дальше я делаю сам, за несколько минут:

* включаю домен в настройках сайта на GitHub (в поле вписывается
  машинное написание);
* пересобираю сайт так, чтобы адреса шли от корня домена
  (`рецепт-тверь.рф/portfolio/`, а не `…/REcept/portfolio/`);
* включаю «Enforce HTTPS», когда GitHub выпустит сертификат;
* перевожу личный кабинет на новый адрес.

### Сроки

Записи расходятся по интернету от 10 минут до нескольких часов
(изредка до суток). Сертификат https GitHub выпускает ещё минут
15–30 после этого. До тех пор сайт продолжает работать по старому
адресу `silovr709-dotcom.github.io/REcept/`.

## Если понадобится админка: хостинг с Node.js или VPS

Самый полный, но и самый хлопотный. Кроме сайта заработают ещё две
вещи, которых нет в статической версии:

* `/admin` — редактирование текстов, фотографий и отзывов прямо на
  сайте, без программиста;
* отправка заявок с форм письмом на вашу почту.

Нужно: Node.js версии 20 или новее, команда `npm ci && npm run build`,
запуск `npm start` под управлением панели или pm2, проксирование
домена на порт 3000 и переменные окружения из `.env.example`.
Если выберете этот путь — напишите, какой у вас хостинг, и я дам
инструкцию под его панель.

## Что уже сделано с моей стороны

* Домен прописан в сайте: canonical-ссылки, `sitemap.xml`, `robots.txt`,
  Open Graph и микроразметка ведут на `рецепт-тверь.рф`.
* Сборка умеет оба режима: в подпапке (GitHub Pages) и от корня домена
  (`npm run build:domain` — папка `site/`, `.htaccess` и `api/lead.php`).
* Приём заявок написан на PHP и входит в архив: письмо на почту плюс
  резервная запись в файл, защита от роботов и потока заявок.
* Адрес нового домена добавлен в разрешённые адреса входа в личный
  кабинет — кабинет заработает на домене сразу, без доработок.
* Проверка качества (`npm run audit`) проходит в обоих режимах.
* Настроена автоматическая выгрузка на хостинг: сборка, проверка,
  отправка только изменившихся файлов по FTP и контроль того, что на
  сайте оказалась именно новая версия (`рецепт-тверь.рф/version.txt`).
* Архив для ручной загрузки собирается сам и лежит по постоянной
  ссылке в разделе Releases — скачанный файл всегда свежий.

## Что останется сделать после переезда

* **Проверить приём заявок.** Отправьте тестовую заявку с живого сайта
  и убедитесь, что письмо пришло. Если нет — впишите пароль приложения
  Яндекс Почты в `api/lead.php`, как описано выше.
* **Яндекс Вебмастер и Яндекс Бизнес.** Подтвердить домен и отправить
  карту сайта `рецепт-тверь.рф/sitemap.xml`, привязать карточку
  организации.
* **Почта на домене** (например, `info@рецепт-тверь.рф`) — это как раз
  удобно сделать на вашем хостинге.
* **Яндекс Метрика.** Счётчика на сайте пока нет: нужен номер счётчика
  из вашего аккаунта Яндекса. Пришлите — поставлю.
